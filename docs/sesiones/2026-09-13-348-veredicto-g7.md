# 2026-09-13 — El auto-etiquetado espera el veredicto G7

## Qué se hizo

- Cada PR elegible contra `dev` dispara `g7-revisar` en `CosteAR-admin` con repositorio, número y SHA completo.
- El consumidor consulta únicamente `G7/datos-de-cliente` sobre ese SHA y sólo `success` permite continuar con G1–G6.
- `failure`, `error`, un dispatch fallido, un PAT ausente o cinco minutos sin status dejan el PR para una persona.
- La prueba roja real del PR #356 apuntó deliberadamente el dispatch a un repositorio inexistente. La corrida 34797455786 no agregó `auto-merge` y registró `NO APTO: G7 no dio veredicto`.

## Recursos

- Tiempo: 16 minutos.
- Tokens: no informado.
- Intentos hasta verde local: 2.
- Comandos ejecutados: `npm ci`, `npm run prisma:generate`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run check:tests-base`, `python scripts/chequear-workflows.py ...`, `git diff --check`.
- La primera corrida de `npm test` tuvo cuatro timeouts de 5 segundos en archivos no modificados; la segunda, ejecutada sin competir con lint/typecheck, pasó 191 archivos y 1655 tests.

## Decisiones que tomé sobre la marcha

- **Qué decidí:** pedir G7 sólo para PRs cuya base es `dev`.
  **Qué otra opción había:** pedirlo también para promociones a `staging`.
  **Por qué elegí esta:** el contrato de admin sólo acepta base `dev`; los commits de una promoción ya atravesaron G7 al entrar en esa rama.
- **Qué decidí:** sondear cada cinco segundos, hasta 60 consultas, y habilitar únicamente `success`.
  **Qué otra opción había:** una espera fija o aceptar cualquier estado terminal distinto de `failure`.
  **Por qué elegí esta:** el sondeo termina apenas llega el verde y conserva el límite máximo de cinco minutos; todo estado no contratado falla cerrado.
- **Qué decidí:** cortar inmediatamente si falta el PAT o falla el dispatch.
  **Qué otra opción había:** esperar cinco minutos aunque se sepa que no existe una solicitud.
  **Por qué elegí esta:** mantiene la puerta cerrada con el mismo mensaje contractual y evita una demora que no puede producir un status.

## Dónde el issue no alcanzaba

- No fijaba el intervalo del sondeo; se eligieron cinco segundos para que el camino normal no agregue minutos perceptibles.
- Decía que `CIRCUITO_PAT` ya estaba disponible desde admin #89, pero la corrida real mostró el secret vacío y la API de Actions no lista ese secret en backend.
- No explicitaba el tratamiento de promociones; se siguió el contrato de admin, que acepta exclusivamente base `dev`.

## Qué quedó afuera

- Los caminos reales `failure` y `success` no pueden ejecutarse hasta que una persona habilite `CIRCUITO_PAT` para `Coste-AR/CosteAR-backend`. No se creó ni modificó el secret porque es infraestructura y una credencial fuera del repo.
- La lista y la lógica privada de detección permanecen en `CosteAR-admin`, como exige #348.
- No se tocaron `auto-merge.yml` ni las guardas G1–G6.
