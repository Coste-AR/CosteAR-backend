# 2026-09-25 — Las horas de cada orden quedan trazables y valorizadas

## Qué se hizo

- Se agregó el parte de horas por persona, orden y etapa, con horas normales y extra.
- La aprobación congela el importe de MOD y escribe la auditoría en la misma transacción.
- La tarifa integral sale del cálculo existente de MOD; no se reescribió el motor.
- La política de prima extra es configurable por empresa: dentro de tarifa por defecto o directa con un adicional aprobado.
- Las etapas de entrega quedan marcadas fuera de la base de horas del taller.
- Un usuario de planta puede cargar y listar sin recibir tarifa ni importe.
- Se publicaron las tres rutas pedidas con OpenAPI y RLS para las dos tablas nuevas.

## Decisiones que tomé sobre la marcha

- **Qué decidí:** representar la tarifa como `TarifaManoObra`, un snapshot versionado de remuneración, horas, ITCS y prima.
  **Qué otra opción había:** tratar `tarifaId` como un UUID opaco o apuntarlo a un período sin poder identificar el departamento.
  **Por qué elegí esta:** permite llamar a `calcDepartmentMod`, evita recalcular historia con valores nuevos y respeta Constitución §2 y §3: no inventa un valor y conserva la unidad económica con el dato.
- **Qué decidí:** no agregar una ruta pública de alta de tarifas.
  **Qué otra opción había:** ampliar el contrato HTTP con endpoints que el issue no definió.
  **Por qué elegí esta:** Constitución §8 y §9 limitan la corrida al issue escrito; el modelo deja el punto de extensión sin inventar permisos ni UX.
- **Qué decidí:** guardar `incluyeBaseHorasTaller` al crear el parte.
  **Qué otra opción había:** consultar `esEntrega` cada vez.
  **Por qué elegí esta:** preserva la clasificación histórica aunque la etapa cambie después.

## Dónde el issue no alcanzaba

- `tarifaId` estaba pedido pero no existía una entidad previa ni se especificaba cómo administrar tarifas. Este PR define el snapshot mínimo y deja su alta pública fuera de alcance.
- `personaId` no tenía una entidad de nómina definida. Se conserva como UUID trazable sin inventar un maestro de personal.
- La base compartida local tenía una migración fallida de #474. La verificación se hizo en una base limpia aislada (`costear_475`) sin modificar ni borrar la base compartida.
- Una primera corrida unitaria tuvo un timeout de `admin-stats` al cargar 248 archivos en paralelo; la repetición completa pasó con 2.038 tests verdes.

## Qué quedó afuera

- Alta y edición pública de tarifas de mano de obra, porque el issue sólo define las rutas de partes.
- Costos directos, entrega, instalación y contingencias, que pertenecen a #476.
