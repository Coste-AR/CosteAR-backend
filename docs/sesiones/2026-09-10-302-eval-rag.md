# Bitácora — issue #302: set dorado + `npm run eval:rag`

## Qué se hizo

- **`tests/rag/eval-runner.ts`** — harness que corre el pipeline completo
  (`VaultRetriever` híbrido + rerank + `VaultQueryService` con generación) contra el set dorado y
  calcula:
  - `recallAt5` — fracción de archivos esperados presentes en los chunks devueltos (leídos de
    `vault_query_log.chunksReturned`, no de un mock)
  - `refusalCorrectRate` — casos trampa (`mustAnswer: false`) en los que el RAG se negó (`NONE`)
  - `sourceHallucinationRate` — casos con una cita a un archivo que NO estaba en el contexto.
    **Objetivo: 0** (es un invariante duro, no una métrica a mejorar)
  - `exactCitationRate` — casos respondidos cuyas citas están todas entre las esperadas
  - `criterionPassRate` — un **juez Claude** (`getLLMService('context')`) evalúa si el `answer`
    cumple el `criterion` del caso
  - `errored` — casos que fallaron por infra/API (no cuentan como regresión)
- **`tests/rag/golden/starter.json`** — 11 casos: 9 `mustAnswer` con `expectedFiles` + `criterion`,
  2 trampa. **Es un STARTER**: se amplía con la auditoría de la cátedra (#290 / F1-03) y con los
  `RAG_MISS` históricos de `daily_signals`.
- **`tests/rag/fixtures/eval-corpus/`** — 5 notas de metodología sintéticas (contribución marginal,
  punto de equilibrio, prorrateo de CIP, absorción vs variable, FIFO). Sin datos de cliente
  (CLI-01). El harness las indexa con `VaultIndexerService` (embeddings reales).
- **`vitest.eval.config.ts`** + `npm run eval:rag`. `tests/rag/eval.test.ts` se **saltea solo** si
  falta `VOYAGE_API_KEY` (CI de quien no tiene la key no rompe). Actualizar la baseline:
  `UPDATE_EVAL_BASELINE=1 npm run eval:rag`.
- **`tests/rag/baseline.json`** — placeholder con `null` hasta la primera corrida real (necesita
  keys sin rate limit). El gate de CI (#303 / F1-13) compara cada corrida contra estos números.
- `tests/db-dependent.mjs`: nueva lista `EVAL_RAG`, incluida en `TESTS_CON_BASE` (la suite rápida
  la excluye, `check:tests-base` la reconoce) pero **no** en `CON_ROL_DE_APP` (no corre con
  `test:integration`).

## Decisiones

- **Runner propio en Vitest, no Promptfoo.** El pipeline necesita una base Postgres viva y el
  código ya vive en Vitest; bolt-on de Promptfoo agregaba una herramienta y un formato nuevos sin
  ganar nada acá. Las métricas siguen el espíritu de RAGAS (context recall, faithfulness) con un
  juez LLM.
- **Resiliencia a fallos de infra**: un caso que tira error de Voyage/Groq/rate-limit se cuenta
  como `errored` y no aborta la corrida. Si `errored === cases`, el test pasa con warning — "no
  poder medir" no es una regresión (eso lo maneja el gate F1-13 aparte).
- **La baseline queda vacía**: en esta máquina la key de Voyage está en el tier sin billing
  (3 req/min) y una corrida completa son >10 min de reintentos; la de Groq devolvió `null`. El
  harness está probado (typecheck, lint, `check:tests-base`, suite rápida en verde) pero la
  baseline real la tiene que generar una corrida con keys sin rate limit (billing de Voyage, o el
  CI con las keys de la org).

El gate de CI que bloquea el merge: #303 (F1-13). Ampliar el set dorado con la cátedra: #290.
